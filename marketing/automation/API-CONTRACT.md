# Marketing automation API contract

Local-only backend for the review UI in `public/`. Bind only to `127.0.0.1:4317`; reject non-loopback hosts and browser origins. JSON responses use UTF-8. Mutation requests require JSON and a same-origin `Origin` when present. No credentials are returned by any endpoint.

## Draft seed and revision

`GET /api/drafts` returns `{ drafts: DraftSummary[] }`; `GET /api/drafts/:id` returns `{ draft: Draft }`. Initial rows are derived from `marketing/content/launch-drafts.json`. Feed slides resolve to generated JPEGs under `marketing/preview/media/jpeg/` and are materialized with `asset: { path, sha256, mimeType, available }`. Reels use local MP4s under `marketing/reels/`, surfaced as `assets: [{ url, sha256, mimeType, available }]`. These are silent typography-only concept storyboards, not recorded footage: `mediaPurpose: "concept_storyboard"` and `mediaDisclosure` are included in the response and approval receipt. UI uses same-origin `/media/{encoded-filename}`; the server serves only registered asset names beneath the configured media roots.

```json
{
  "id": "feed-01",
  "title": "A city feels smaller when you know someone there",
  "platforms": ["instagram", "facebook"],
  "status": "draft",
  "caption": "...",
  "hashtags": ["#CharlotteNC"],
  "slides": [
    { "headline": "...", "body": "...", "asset": { "path": "/media/feed-01-01.jpg", "sha256": "...", "mimeType": "image/jpeg", "available": true } }
  ],
  "assets": [{ "name": "feed-01-01.jpg", "url": "/media/feed-01-01.jpg", "sha256": "...", "mimeType": "image/jpeg", "available": true }],
  "mediaReady": true,
  "revision": 1,
  "contentSha256": "..."
}
```

`contentSha256` is computed from canonical JSON for exact text and slide order, platform-relevant caption, all media byte hashes, and draft ID. Revision, destination, action and scheduled time are separately bound into each immutable approval. Any text, caption, image, asset bytes, order, destination, action or schedule change requires a new approval. The concept Reels are video assets but must be reviewed with the disclosure; the UI does not represent them as recorded scenes.

## State and approvals

- `GET /api/status` returns `{ server: { bind, port }, publishingEnabled, connected, accounts, oauthReady, pendingApprovals, discovery }`; `discovery` contains readiness, required/granted/missing permissions, and the count of linked Instagram accounts.
- `GET /api/calendar` returns the 30-day relative outline in `marketing/content/launch-drafts.json`; it is never treated as a schedule or authorization to publish.
- `GET /api/accounts` returns `{ accounts: [{ id, platform, name, pageId?, instagramUserId?, accountType, permissions, connected }] }`. No account IDs are seeded; this remains empty until a user explicitly connects Meta.
- `PUT /api/drafts/:id` accepts `{ expectedRevision, expectedContentSha256, title?, caption?, cta?, hashtags? }`. The server rejects stale editor state, increments revision, recomputes the exact content/media hash, and invalidates outstanding approvals. Feed slide text and Reel timed scripts/shot lists are read-only until a renderer can regenerate the matching media/subtitles; the server rejects script edits with `media_sync_required`. Media paths/hashes cannot be supplied by the browser.
- `POST /api/drafts/:id/decision` accepts `{ revision, contentSha256, decision: "reject"|"request_changes", note, reviewer }`; it records the decision and a text/media-hash snapshot against that exact revision/hash. The draft itself remains a draft.
- `GET /api/provider` returns `{ provider, model, enabled, budgetUsd, spentUsd }`. Defaults are `provider: "none"`, `enabled: false`, and budget/spend `0`; no model is selected implicitly.
- `POST /api/drafts/:id/regenerate` accepts `{ expectedRevision, expectedContentSha256, prompt }`. It returns `503 provider_disabled` unless an explicit provider and positive budget are configured. `template` performs a local zero-cost copy transformation; `openai` also requires an API key, explicit model, input/output token rates, and a positive budget. Any result is a new revision and never becomes approved. No provider is enabled by default.
- `POST /api/approvals` accepts `{ draftId, revision, contentSha256, target: { platform, accountId }, action, scheduledAt, approver }`. `action` is `publish_now` or `schedule`; `scheduledAt` is null for `publish_now` and a future ISO-8601 timestamp for `schedule`. The server resolves the real connected account and actual media bytes, recomputes SHA-256, enforces Instagram’s caption length, and rejects mismatched or missing media. It stores an immutable approval record with exact content, caption, text/media hashes, target, action, time, reviewer and revision/hash. There is no default approver identity; the local UI must capture an explicit name/identity.
- `GET /api/approvals` returns `{ approvals: [...] }`; `GET /api/activity` returns `{ items: [...] }` newest first. Durable records include approvals, every external-action attempt, Graph/container IDs, completion/failure/unknown outcome, and timestamps. Audit history is append-only through the HTTP API.
- `POST /api/approvals/:id/revoke` accepts `{ reason }`. A serialized state transaction allows revocation only before execution claims the approval; once an attempt exists, revocation is rejected.
- `POST /api/attempts/:id/resolve` accepts `{ resolution: "confirmed_published"|"confirmed_not_published", reviewer, note }`. This records human reconciliation of an `outcome_unknown` attempt. It never retries the external action.
- `GET /api/discovery/candidates` returns `{ candidates: [...] }` from local review storage.
- `POST /api/discovery/instagram/collect` accepts `{ accountId: "instagram:<linked-user-id>", username: "venuehandle" }` after same-origin validation. It requires an existing linked Instagram account and the encrypted Facebook user token with `instagram_basic`, `instagram_manage_insights`, and `pages_read_engagement`. It performs one explicit Graph v26 request using the logged-in account's IG ID, stores at most the first 25 public media records as deduplicated local candidates, and returns collection/new/duplicate/invalid counts with `moreResultsMayExist: true`. It never pages for completeness, extracts event dates, or writes Yard events. Candidate rows retain source post ID, permalink, caption, source timestamp, media type, and an optional documented `media_url`; they start as `reviewStatus: "unreviewed"`. Missing media URLs are allowed (Meta can omit them for some video). URLs are stored as source metadata and are not downloaded by the service. [Meta Business Discovery](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery), [Meta Instagram Media fields](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media)
- `POST /api/discovery/following/import` accepts a parsed export `{ relationships_following: [...] }`, with each relationship using Instagram's `string_list_data[].value` username field. It is JSON only, within the server's 1 MB request cap and 20,000 relationship limit. Usernames are sanitized and deduplicated case-insensitively into local leads; entries without a valid `value` are counted invalid. `GET /api/discovery/leads` returns `{ leads: [...] }`. Imported leads have `status: "unverified"`; following an account is not evidence that it is a Charlotte venue, an organizer, a professional account, or API-eligible. Import performs no Meta call and does not create a post candidate or Yard event.
- `GET /api/discovery/quota` returns `{ quota: { used, limit: 30, windowDays: 7, remaining, attempts } }`. `used` counts unique hashtags attempted in the rolling seven-day window. Attempts are conservatively counted before Graph requests and remain counted when Meta rejects or times out; quota exhaustion prevents a new unique hashtag, but a hashtag already attempted in-window may be retried by explicit user action.
- `POST /api/discovery/instagram/hashtag/collect` accepts `{ accountId: "instagram:<linked-user-id>", hashtag: "cltevents" }` (a leading `#` is stripped). It requires a connected linked Instagram professional account, Facebook USER token, `instagram_basic` and `pages_read_engagement`, plus Meta-approved Instagram Public Content Access for the app. The server resolves `user_id` from the selected linked account; callers cannot override the Graph account ID. One user-initiated collection runs `GET /ig_hashtag_search?q=...` then `GET /{hashtag-id}/recent_media?fields=id,caption,timestamp,permalink,media_type&limit=25`, with no paging. At most 25 posts are stored as review-only candidates. For hashtag-only candidates `sourceUsername` is null and `sourceHashtag` is the normalized hashtag. Candidates deduplicated with Business Discovery preserve both entries in `sourceAttributions`; the existing source username is not overwritten. The timestamp is the source post time, never an inferred event time. Meta errors remain sanitized `meta_*` failures; they are not treated as evidence of a personal account or an unqualified source. No event fields are extracted and no Yard event is written. [Meta Instagram Hashtag Search](https://developers.facebook.com/docs/instagram-api/guides/hashtag-search/)

## Event draft export to the owner inbox

- `GET /api/event-review/status` returns `{ enabled: true, liveWrites: false, draftsCount, exportableCount }`.
- `GET /api/event-review/drafts` returns `{ drafts: [...] }`. `POST /api/event-review/drafts` accepts `{ candidateId }` for an existing Instagram post candidate and creates a distinct editable draft with blank event fields. It does not copy the source caption into `details`. Each draft includes a fixed source snapshot, `candidateId`, `revision`, and `status`; multiple event drafts may reference one post. Source `link` and generated `source_handle` cannot be edited.
- `PUT /api/event-review/drafts/:id` accepts `{ expectedRevision, title, starts_at, ends_at, venue, address, details, evidenceNotes, referenceUrls }` with any subset of editable fields. It rejects stale revisions and overlength text instead of truncating. Dates must be ISO 8601 with an explicit offset matching `America/New_York` for the event date, including DST. Start time must be in the future and within 30 days; an optional end time must follow the start. Text limits mirror the inbox validator: title 120, venue 120, address 200, details 1,000, source handle 100, and link 500 characters. Evidence notes and HTTPS reference URLs remain local-only.
- `POST /api/event-review/drafts/:id/reject` accepts `{ expectedRevision, reason }` to keep rejected candidates out of the export. A draft becomes exportable when its required fields are complete; it does not receive a fabricated reviewer or approval.
- `GET /api/event-review/export` returns `{ events: [...] }` for complete non-rejected drafts only, deduplicated by normalized title, start minute and venue. Export fails closed above 50 events or 256 KiB of serialized UTF-8 JSON. Each event contains only the inbox's permitted fields: required `title`, `starts_at`, plus optional `ends_at`, `venue`, `address`, `link`, `details`, and generated `source_handle`. Link is fixed to the Instagram source post; source handle is `instagram:<username>` or `instagram:#<hashtag>`. No status, coordinates, price, or local provenance fields are submitted. Time offsets are preserved in this JSON. The UI downloads the response as `events.json`.
- Export is a draft file only. The local service never reads `YARD_AGENT_SECRET`, sends HTTP to Supabase, or writes a Yard event. The owner must inspect `events.json`, submit it using the separately documented agent-inbox owner procedure, review the pending rows in Studio, and approve there. The inbox validates an exact eight-key allowlist, maximum 50 events and 256 KiB, deduplicates repeats, and creates pending submissions; nothing is public until owner approval.

## Publishing and failure states

- `POST /api/approvals/:id/execute` is a separate, explicit action. The server rechecks the approval hash, exact account, media files, and action/time before doing anything. `publish_now` is executable only from a user click; `schedule` is queued for the approved time. The scheduler and endpoint both honor the server-side publish flag.
- `YARD_META_PUBLISH_ENABLED` defaults to `false`. When false, OAuth account read/discovery may be manually initiated, but every publish/execute attempt returns `403 publishing_disabled` and makes no Graph write request. Tests use mocked Graph transport only. No live credentials or publication are part of this build.
- Each operation has a unique lock over `(platform, accountId, contentSha256, action, scheduledAt)`. Persist an execution claim and `preparing` attempt atomically after re-reading the stored approval, destination and draft state. Revocation and execution serialize against this claim. On an ambiguous timeout, use `outcome_unknown`, hold the lock, and require reconciliation or explicit human resolution; never blindly retry. On startup, any interrupted `preparing` attempt is promoted to `outcome_unknown`, because a previous process may have reached Meta. Successful publication stores the returned platform media/post ID and marks the attempt complete.
- Graph calls pin Meta Graph API v26.0, verified from current primary Meta Pages and Instagram documentation; `YARD_META_GRAPH_VERSION` can override only when explicitly set. Facebook text uses Page `/{page-id}/feed`. A carousel is assembled at approved execution time by uploading photos with `published=false`, then posting the caption and `attached_media` array to `/feed`. Single-photo uses `POST /{page-id}/photos` with `url` and `caption`. The local scheduler runs an approved schedule after its exact time. Facebook video/Reel publishing and Stories are not implemented. [Meta Page Posts v26.0](https://developers.facebook.com/documentation/pages-api/posts), [Meta Page Photos v26.0](https://developers.facebook.com/docs/graph-api/reference/page/photos/)
- Instagram images/carousels use the Page-linked professional-account flow: each image is a JPEG media container; carousel child containers set `is_carousel_item=true`; the parent uses `media_type=CAROUSEL`, comma-separated `children`, and caption; publish the parent using `/media_publish`. Reels use `media_type=REELS`, a public video URL, status polling, then `media_publish`. Instagram Stories are not implemented. Instagram carousels are limited to 20 children. [Meta Instagram content publishing v26.0](https://developers.facebook.com/documentation/instagram-platform/content-publishing)
- All image/video URLs passed to Meta must be public HTTPS URLs. The server maps each registered local asset to a hash-addressed URL under `YARD_META_MEDIA_BASE_URL` (`/{sha256}/{filename}`) and first fetches that URL, requiring remote bytes to match the approved local SHA-256. Configure the public host as an immutable/content-addressed media mirror; if no mirror is configured or bytes differ, execution stops before Graph write. Generated 1080×1350 JPEG copies are the image candidates for both Instagram and Facebook.
- Read Instagram publishing quota at execution and use a conservative lower ceiling until Meta’s per-format quota documentation is harmonized. Do not exceed the live returned quota. Page and IG posting permissions/roles are checked from the connected account before approval/execute. Current Graph version is explicitly pinned and reviewable.
- `GET /api/insights` returns `501 insights_not_implemented` in this first backend. No metric list is guessed; add it after current permission and per-media metric contracts are verified.

## Meta connection

- `GET /api/meta/oauth/start` creates one-time, expiring CSRF `state` and redirects to the fixed Facebook Login authorize URL/callback URI. Callback URI is `http://127.0.0.1:4317/oauth/meta/callback` and must exactly match the developer app configuration. The browser return is local only.
- `GET /oauth/meta/callback` validates and consumes state before exchanging the one-time code server-side, exchanges for a long-lived user token, encrypts tokens at rest, then resolves Page tokens and linked professional Instagram accounts. `POST /api/meta/disconnect` revokes local connection state and deletes encrypted token material; it does not delete the Meta app or Page.
- OAuth state is mandatory. S256 PKCE may be sent only when explicitly enabled and supported by the configured Meta Login flow; otherwise fail closed rather than inventing token-exchange semantics. State and verifier are one-time and expire quickly.
- Permissions are the minimal configured set for the selected action. No token, code, app secret, OAuth error description, or Authorization header is included in API responses or logs.

## Errors

Errors use `{ error: { code, message, requestId? } }`. Stable codes include `invalid_request`, `not_found`, `approval_mismatch`, `asset_missing`, `media_sync_required`, `account_not_connected`, `oauth_not_configured`, `oauth_state_invalid`, `publishing_disabled`, `approval_not_revokeable`, `duplicate_locked`, `outcome_unknown`, and `meta_error`. Public messages are sanitized. Request bodies, tokens, OAuth query values, and Graph URLs are never logged.
